1. EXECUTIVE SUMMARY
================================================================================
CareCircle has been transformed from a single-tier caregiver dashboard into an
enterprise-grade, multi-role care coordination platform with strict server-side
authorization boundaries across three distinct operational actors:
1. Administrator (System oversight, user lifecycle, verifications, audit logs, payroll)
2. Caregiver (Daily clinical tracking, medications, vitals, checklists, notes)
3. Family Member (Patient-scoped, read-only peace-of-mind portal, refill delegation)

All clinical and patient data is isolated by database relations and enforced on
the server side. Client-side navigation hiding serves only cosmetic convenience;
every API endpoint and Server Component independently validates permissions.

2. PHASE-BY-PHASE IMPLEMENTATION BREAKDOWN
================================================================================

--------------------------------------------------------------------------------
PHASE 0: SECURITY & CRYPTOGRAPHY HARDENING
--------------------------------------------------------------------------------
- Signed Expiring JWT Sessions (jose HS256):
  * Replaced insecure base64("role:id") cookie encoding with signed HS256 JWT tokens.
  * Tokens store { sub: userId, role, tokenVersion } signed with SESSION_SECRET.
  * Throws startup fatal error if SESSION_SECRET is shorter than 32 characters (no fallback).
  * Cookie settings: httpOnly, sameSite: "lax", path: "/", maxAge: 7 days.
  * Removed legacy no-colon fallback completely. Tampered or forged tokens return null.
- Token Invalidation & Session Revocation:
  * Added `tokenVersion Int @default(0)` to Admin, Caregiver, and FamilyMember models.
  * Changing password or administrative account lockout increments tokenVersion,
    instantly terminating active sessions across all devices.
- Rate Limiting & Auth Protection:
  * In-memory sliding-window rate limiter on /api/auth/login (5 failed attempts / 15m).
  * Generic "Invalid email or password" returned for both non-existent users and wrong passwords.
  * Demo login (/api/auth/demo-login) restricted strictly to non-production environments
    with ENABLE_DEMO_LOGIN=true, explicitly forbidding ADMIN logins.
- Secret Hygiene:
  * .gitignore hardened for .env, .env.local, .env*.local, *.db, *.db-journal, tsbuildinfo.
  * .env.example created with clean placeholder keys and no real secrets.

--------------------------------------------------------------------------------
PHASE 1: DATABASE RE-ARCHITECTURE & PRISMA MIGRATIONS
--------------------------------------------------------------------------------
- Multiple Family Members per Patient:
  * Removed @unique constraint on FamilyMember.patientId to allow multiple family
    contacts (e.g. Son, Daughter, Spouse). Added @@index([patientId]).
- Relationship Standardization:
  * Added relationship enum string: SON | DAUGHTER | SPOUSE | SIBLING | GRANDCHILD | PARENT | FRIEND | OTHER.
  * Added relationshipOther String? for custom specifications.
  * Added isPrimaryContact Boolean @default(false) with automatic single-primary enforcement.
- Operational & System Models:
  * AuditLog: Tracks actorType, actorId, action, targetType, targetId, summary, ip, timestamp.
  * Caregiver.verificationStatus: PENDING | VERIFIED | REJECTED with rejectionReason String?.
  * SystemSetting: Key-value store for overdueDoseMinutes, refillWarningDays, alertEscalationHours, alertRecipientEmails.
  * NotificationPreference: Granular alert toggles per userType & userId.
  * Conversation & Message: Patient-circle messaging channel with sender roles and read receipts.
  * CareNote: Shift notes (SHIFT_NOTE) and shift handovers (HANDOVER).
  * LoginAttempt: Security telemetry recording IP, email, success/failure timestamp.

--------------------------------------------------------------------------------
PHASE 2 & 3: UNIFIED USERS MANAGEMENT & AUTHORIZATION
--------------------------------------------------------------------------------
- Unified User Management (/admin/users):
  * Single interface to create, view, edit, deactivate, reactivate, and reset passwords
    for Admins, Caregivers, Patients, and Family Members.
  * Email uniqueness enforced across Admin, Caregiver, and FamilyMember tables (409 Conflict).
  * Admin deactivation lock: Prevents deactivating the last remaining active administrator.
  * Automatic Primary Contact Unsetting: Setting a family member as primary contact
    automatically demotes previous primary contacts for that patient.
  * Caregiver Assignment Validation: Only VERIFIED caregivers can be assigned to patients.
